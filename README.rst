im_hobo (MET_hobo)
===================

.. Zenodo DOI badge
.. image:: https://zenodo.org/badge/1356725647.svg
  :target: https://doi.org/10.5281/zenodo.22294811

This module performs basic QAQC on CSV files generated by Onset HOBO loggers, creating a directory of
.hobo and CSV files formatted for easy import into the GCE Matlab toolbox.

See `module documentation <https://im-hobo.readthedocs.io>`_ for use.

Data QA Performed:
--------------------
#. Columns that are empty or have erroneous text are removed,
#. timezone is checked and converted to a user defined value,
#. measurement units are checked and values converted to user defined units, and
#. timestep is synced to a standardized interval; Exp: tstep='5min',  11:05:35 becomes 11:05:00.

File Management Performed
-------------------------
All files are removed from the source directory and filed for storage. File movement is tracked in log files.

Accepted File Format
====================
There are many different export options for converting .hobo files to .csv in HOBOware, however not all formats can
be processed by this module.

A set of acceptable file formats, and invalid file formats are provided as an example in this repository's
test cases (see ``dev_tests/``).

Format Requirements
-------------------
* U.S. Date formats only: MDY or YMD
* U.S. Number formats only: -1,000.0 or -1000.0

Including GMT
--------------
A primary function of this module is correcting time zone. Because each sensor does not have its own clock and simply
counts time from the Launcher or PC clock, daylight savings is often included or excluded inconsistently throughout the
life of a sensor. For this reason, time zone (GMT -#) must be included in the header so that it can be converted to the
user's standard.

To export time zone from HOBOware:

#. Go to Preferences>>General>>Export Settings
#. *DE-SELECT* option, "No quotes or commas in headings, properties in parentheses"

Installation
============
Requires Python 3.11 or later. Two installation methods are supported: ``pip`` (recommended) or ``conda``.

Using pip
---------
From a clone of the repository:

.. code-block:: bat

    pip install .

For development (editable install, plus the test suite dependencies):

.. code-block:: bat

    pip install -e .[test]

Using conda
-----------
A conda environment file is also provided. To create a python installation that has all necessary packages
installed to run this program, install conda and type the following commands into a terminal:

.. code-block:: bat

    conda env create -f conda_environment.yaml

    conda activate im_hobo

Your screen should now display:

.. code-block:: bat

    (im_hobo)c:/my_work_dir/>

You can now use the process described below to run the program. It will only allow you to use the python version
and packages listed in the :code:`conda_environment.yaml` project. To exit this python environment when you are
done working, type:

.. code-block:: bat

    conda deactivate

Run the Program
================
Create and edit file_path.config
---------------------------------
``file_path.config`` is machine-specific and is not tracked in git. Copy the provided template and edit your copy:

.. code-block:: bat

    copy file_path.config.example file_path.config

Then edit ``file_path.config`` to define the three file directories (source, working, final). Timestamp syncing is
disabled by default in this version and only runs when a ``time_step`` is explicitly passed at runtime. Take care to
use ``\\`` for Windows file paths or ``/`` which will work on any operating system. NEVER use
``\`` which is a special character; example:

.. code-block:: python

    In[36]: print('c:\new\forest\temp\nc:\\new\\forest\\temp')
    Out[36]: c:
            eworest	emp
            c:\new\forest\temp

``file_path.config`` is found automatically, in this order: (1) an explicit path passed to
``FileHandling(config=...)`` or ``--config``, (2) the ``IM_HOBO_CONFIG`` environment variable if set,
(3) ``file_path.config`` in the current directory, (4) ``file_path.config`` in the repository root.
This means it's found whether you run from the repository root or from ``MET_hobo/``, with no need to
place it anywhere in particular unless you want to override it per-run.

Deduplication (optional)
-------------------------
Files pass through three stages, each with its own directory:

#. ``dir_source_files`` — the original HOBOware exports.
#. ``dir_final_storage`` — the cleaned CSV/TOA5/Parquet output of the QAQC pipeline.
#. The dedupe output directory — a further-deduplicated copy of ``dir_final_storage``, produced only
   when ``dedupe_mode`` is ``"auto"`` or ``"prompt"`` (default: ``"off"``, skipped).

By default, the dedupe output directory is a sibling of ``dir_final_storage`` named
``<dir_final_storage name>_dedup`` — e.g. a ``dir_final_storage`` of ``.../bulk_clean`` defaults to
``.../bulk_clean_dedup``. Set the optional ``dir_dedupe_output`` key in ``file_path.config`` to send
it somewhere else instead. See the commented-out example in ``file_path.config.example``.

Every CSV written to the dedupe output directory (copied unchanged or truncated) carries its
``TOA5/<name>.dat`` and ``parquet/<name>.parquet`` siblings along with it, into matching ``TOA5/``
and ``parquet/`` subdirectories of the dedupe output directory — so the dedupe output is a complete,
ready-to-process set in all three formats, not just CSV. A CSV missing one or both siblings (e.g.
when routing output to per-project site directories, where TOA5/Parquet aren't written) is skipped
silently for that format rather than erroring.

Accessing the Methods
---------------------
From Python
^^^^^^^^^^^
Import the module and access the individual classes and methods directly. This allows parameters to be set directly.

``FileHandling.manage()`` will run the process on all files in a directory from start to finish.

From Terminal
^^^^^^^^^^^^^
The entire batch process can be initiated from a terminal. Run as a module from the repository root
(this is the recommended way to run it, whether installed via ``pip`` or run from a clone):

.. code-block:: bat

    rem batch execute HOBO QAQC, from the repository root
    python -m MET_hobo.file_manager

    rem override which file_path.config to use
    python -m MET_hobo.file_manager --config path\to\file_path.config

Running ``python file_manager.py`` directly from inside ``MET_hobo/`` also still works, and resolves
``file_path.config`` the same way.

To manually control time step, units, or time zone **from the terminal**:

.. code-block:: bat

    rem edit QAQC settings of batch, from the repository root
    python -c "from MET_hobo.file_manager import FileHandling; FileHandling().manage(time_step='20min')"

TOA5 and Parquet Output
========================
In addition to the standard GCE-formatted CSV output, every processed file is also written as a
Campbell Scientific TOA5 file and an Apache Parquet file. This happens automatically for every run in
bulk mode (``final_subdirs=False``, the default) - there is no separate flag to turn it on. It is not
yet supported when routing output to per-project site directories (``final_subdirs=True``); in that
mode, only the CSV output is written.

Output is written alongside the existing CSV output, under new subdirectories of the final storage
directory:

* ``dir_final_storage/TOA5/<filename>.dat``
* ``dir_final_storage/parquet/<filename>.parquet``

Both writers include a ``Sitecode`` field, extracted automatically from each source filename
(``extract_sitecode()``).

TOA5
----
The TOA5 file is a 4-line Campbell Scientific ASCII header followed by data rows — ``Temp`` in
``Deg C`` and ``Intensity`` in ``lux``, matching the only units path currently supported
(``units='SI'``). The aggregation code is always ``Smp`` (HOBO records are instantaneous samples, not
computed aggregates). Missing values are written as ``NAN``.

The station, logger model, serial number, table name, OS version, and program name/signature fields
in the TOA5 header are optional and default to empty strings. Set them in ``file_path.config`` with
the ``toa5_station``, ``toa5_logger_model``, ``toa5_serial``, ``toa5_table_name``,
``toa5_os_version``, ``toa5_program_name``, and ``toa5_program_sig`` keys — see the commented-out
examples in ``file_path.config.example``. If ``toa5_serial`` is not set, the logger serial number
parsed from the source file's header (``LGR S/N:``) is used instead.

Example output (``station='MS045'``, ``logger_model='HOBO-Pendant'``, ``table_name='Table1'``)::

    "TOA5","MS045","HOBO-Pendant","12345","","","","Table1"
    "TIMESTAMP","RECORD","Sitecode","Temp","Intensity"
    "TS","RN","","Deg C","lux"
    "","","Smp","Smp","Smp"
    "2024-06-01 00:00:00",0,"PA002",12.5,100
    "2024-06-01 00:15:00",1,"PA002",NAN,200.5

Parquet
-------
The Parquet file preserves real dtypes (a timezone-aware timestamp column, native float columns) and
null values, with Snappy compression by default. Column units (``Deg C`` / ``lux``) are attached as a
``units`` key in each field's Parquet metadata, so downstream readers can label columns without
needing to know this is HOBO data.

CSV Date Summary GUI
====================
The repository also includes a small GUI utility for reviewing the date range in a folder of CSV files, and for
deduplicating overlapping exports of the same sensor. It scans each ``.csv`` file in the selected directory and
reports filename, start date, end date, record count, and status.

From the repository root:

.. code-block:: bat

    python MET_hobo\hobo_date_summary.py

Use **Browse...** to select a folder, **Scan** to load the file summaries, and **Save Summary CSV** to export the
results.

Settings Dialog and Pipeline Run (GUI)
---------------------------------------
The same GUI's **Pipeline > Settings...** menu item opens a dialog for editing ``file_path.config``
without a text editor, and for running the full QAQC pipeline from there directly.

* One row per config key (the three required directories, ``time_step``, ``dedupe_mode``,
  ``dir_dedupe_output``, ``map_fname2dir``, and the ``toa5_*`` fields), each with a **Browse...**
  button for directory fields and a short "(?)" tooltip explaining what it does.
* **Save** writes ``file_path.config`` to whichever path it would otherwise be found at (see
  the resolution order above), or to the repository root if none existed yet — seeding the
  dialog's fields from ``file_path.config.example`` in that case. Directories that don't exist
  yet trigger a warning (not a hard stop), and output directories can be created on the spot.
* **Run** (enabled once Save succeeds) runs ``FileHandling(config=...).manage()`` in a background
  thread, so the dialog stays responsive. A scrolled log pane shows progress live, followed by a
  completion summary or the failing exception's traceback. If ``dedupe_mode`` is ``"prompt"``,
  the console y/N prompt is shown as a Yes/No dialog instead of blocking silently.
* Every run's full log is also saved to ``<dir_final_storage>/logs/gui_run_<timestamp>.log`` —
  the same ``logs/`` directory ``FileHandling.write_log`` already uses, just with a
  GUI-specific filename — and that path is shown in the log pane once the run finishes.

The **Help** menu opens this project's documentation (https://im-hobo.readthedocs.io) in your
default browser.
